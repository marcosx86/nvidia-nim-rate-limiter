Yes. Given your goal—**Hermes → iron-proxy → NVIDIA NIM, with the real `nvapi-*` key never exposed to the sandbox and a hard request rate limit**—I'd use a tiny Python reverse proxy rather than NGINX.

The important topology is:

```text
Hermes sandbox
      │
      │ opaque iron-proxy credential
      ▼
iron-proxy :8080
      │
      │ real NVIDIA credential injected
      ▼
rate-limit proxy :8000
      │
      │ NVIDIA_API_KEY
      ▼
integrate.api.nvidia.com
```

However, there's a subtle problem with putting the limiter **after** iron-proxy: the limiter process then has access to the real NVIDIA key. That's acceptable if it runs on the same trusted host, but it means the key exists in two trusted processes instead of only iron-proxy.

A better design is:

```text
Hermes
  │
  ▼
iron-proxy
  │
  │ localhost
  ▼
NVIDIA rate-limit proxy
  │
  ▼
NIM
```

The sandbox still never gets the real key.

## 1. Create the limiter

Directory:

```bash
mkdir -p /opt/data/nvidia-nim-ratelimit
cd /opt/data/nvidia-nim-ratelimit
```

Create `app.py`:

```python
import asyncio
import os
import time

import httpx
from fastapi import FastAPI, Request
from fastapi.responses import Response

app = FastAPI()

NVIDIA_API_KEY = os.environ["NVIDIA_API_KEY"]

UPSTREAM = "https://integrate.api.nvidia.com"

# Hard limit: 6 requests / 60 seconds.
REQUESTS_PER_MINUTE = 6
WINDOW_SECONDS = 60.0

# Serialize requests. This is particularly useful with NIM quotas.
lock = asyncio.Lock()
request_times: list[float] = []

client = httpx.AsyncClient(
    base_url=UPSTREAM,
    timeout=httpx.Timeout(
        connect=10.0,
        read=300.0,
        write=300.0,
        pool=300.0,
    ),
)


async def acquire_slot():
    global request_times

    while True:
        async with lock:
            now = time.monotonic()

            request_times = [
                t for t in request_times
                if now - t < WINDOW_SECONDS
            ]

            if len(request_times) < REQUESTS_PER_MINUTE:
                request_times.append(now)
                return

            wait_for = WINDOW_SECONDS - (now - request_times[0])

        await asyncio.sleep(wait_for)


@app.api_route(
    "/{path:path}",
    methods=[
        "GET",
        "POST",
        "PUT",
        "PATCH",
        "DELETE",
        "OPTIONS",
        "HEAD",
    ],
)
async def proxy(path: str, request: Request):
    await acquire_slot()

    body = await request.body()

    headers = dict(request.headers)

    # Never forward the client's Authorization header.
    headers.pop("authorization", None)

    # The limiter owns the real NVIDIA credential.
    headers["Authorization"] = f"Bearer {NVIDIA_API_KEY}"

    # These should be generated by the upstream connection.
    headers.pop("host", None)
    headers.pop("content-length", None)

    upstream_path = "/" + path

    if request.url.query:
        upstream_path += "?" + request.url.query

    upstream_response = await client.request(
        request.method,
        upstream_path,
        headers=headers,
        content=body,
    )

    response_headers = dict(upstream_response.headers)

    # Don't expose hop-by-hop headers.
    for h in (
        "content-length",
        "transfer-encoding",
        "connection",
    ):
        response_headers.pop(h, None)

    return Response(
        content=upstream_response.content,
        status_code=upstream_response.status_code,
        headers=response_headers,
        media_type=upstream_response.headers.get("content-type"),
    )
```

This gives you a **fixed-window 6 RPM limiter** and **one request at a time**.

## 2. Dockerfile

Create:

```text
Dockerfile
```

with:

```dockerfile
FROM python:3.13-slim

WORKDIR /app

RUN pip install --no-cache-dir \
    fastapi \
    uvicorn[standard] \
    httpx

COPY app.py .

USER nobody

CMD [
    "uvicorn",
    "app:app",
    "--host", "0.0.0.0",
    "--port", "8000",
    "--workers", "1"
]
```

**Keep `--workers 1`.**

The limiter's request state is in memory. Multiple workers would each have their own six-request counter and could therefore defeat the limit.

# 5. Configure iron-proxy → limiter

This is where we need to be careful with your existing setup.

Your current chain should ultimately point NIM traffic at:

```text
127.0.0.1:8000
```

rather than directly at:

```text
integrate.api.nvidia.com
```

The rate limiter then handles:

```text
http://127.0.0.1:8000/v1/chat/completions
```

and forwards it to:

```text
https://integrate.api.nvidia.com/v1/chat/completions
```

### But don't blindly add this to `proxy.yaml`

```yaml
upstream: http://127.0.0.1:8000
```

because **iron-proxy 0.39's configuration schema does not have a generic provider `upstream` directive in the way I'm describing**.

Your earlier empty `proxy.yaml` is significant here.

We need to configure the **NIM host mapping in the actual iron-proxy mechanism**, not invent a YAML key.

# 6. One change I'd make to the Python proxy

There's another important issue for an LLM proxy: **streaming**.

Hermes/NIM may use:

```json
"stream": true
```

The simple implementation above buffers the entire HTTP response before returning it. That is undesirable for an interactive agent.

I'd therefore actually use a streaming implementation for your Hermes deployment.

The key difference is:

```text
NIM
 │
 │ chunks
 ▼
rate limiter
 │
 │ chunks immediately
 ▼
Hermes
```

rather than:

```text
NIM
 │
 │ entire response
 ▼
rate limiter
 │
 │ entire response
 ▼
Hermes
```

For an agent, the first is much better.

## 7. About what "6 RPM" actually means

The implementation above is a **request-start limiter**, not a token limiter.

So:

```text
12:00:00  request #1
12:00:00  request #2
12:00:00  request #3
12:00:00  request #4
12:00:00  request #5
12:00:00  request #6

12:00:01  request #7 → waits
...
12:01:00  request #7 → allowed
```

That's useful if NVIDIA's quota is expressed as **requests per minute**.

If your NIM entitlement instead says something like:

```text
60 RPM
100,000 TPM
```

then RPM alone isn't enough. You'd want **both request and token limiting**.

For Hermes, I would also strongly recommend keeping:

```text
concurrency = 1
```

because otherwise six long-running NIM requests can occupy your quota simultaneously.

## 8. What I would use for your setup

Given your Hermes/iron-proxy setup, I'd configure it as:

```text
                    UNTRUSTED
┌─────────────────────────────────────┐
│ Hermes sandbox                      │
│                                     │
│ NVIDIA_API_KEY = proxy-token       │
└──────────────────┬──────────────────┘
                   │
                   ▼
             iron-proxy
             :<proxy-port>
                   │
                   │ real nvapi key
                   ▼
        ┌──────────────────────┐
        │ NIM rate limiter     │
        │                      │
        │ 6 requests / minute  │
        │ concurrency = 1      │
        │ streaming            │
        └──────────┬───────────┘
                   │
                   ▼
       integrate.api.nvidia.com
```

The **real NVIDIA key never enters the Hermes sandbox**.

And importantly, the limiter itself is bound to:

```text
127.0.0.1:8000
```

so it isn't another network-accessible credential endpoint.

### One more improvement

For production I'd change the fixed-window limiter to a **token bucket**. That avoids the ugly boundary behavior where six requests can theoretically occur at `12:00:59` and another six at `12:01:00`.

If NVIDIA gives you a hard **6 RPM** quota, a token bucket configured to **6 capacity / 1 token every 10 seconds** is much more predictable.
